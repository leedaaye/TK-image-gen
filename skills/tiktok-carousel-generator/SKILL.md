# TikTok 图文带货生成 Skill（Agent 原生执行）

## 执行原则

你就是分析、策划和提示词编写模型。直接用当前会话的推理与看图能力完成这些步骤，再调用宿主已提供的生图工具出图。

- 不向用户索取 API Key、Base URL 或模型名称；不查找、读取、提取宿主的密钥。
- 不安装 Python、依赖包、插件或服务，不运行旧 CLI，不访问项目数据库，不要求启动 Web 应用。
- 生图使用现有工具的既有配置。此 Skill 不新增模型配置，也不承诺宿主工具免费。
- 先读当前可用工具的说明，按真实参数调用；不要假设任意 Agent 都有同名工具或相同参数。
- 用户已要求生成图片且资料足够时，直接完成策划与出图，不反复要求确认。若用户仅要求方案/提示词，输出策划后停止。遵守宿主实际权限与审批要求。
- 当前任务只是安装、修改或分享此 Skill 时，不要顺带调用生图工具做收费样例。

## 适用场景

用户提供商品信息、参考图与目标市场，要求制作 TikTok Photo Mode 带货图文；或要求修改其中一张。默认6张、3:4竖图、统一视觉风格，用户指定数量、比例、语言和方向优先。通常4–10张；不要为了套模板凑数。

## 1. 读取资料，建立事实边界

1. 阅读用户商品说明，用现有看图工具查看参考图；附件、文件路径与链接按宿主的读取方式处理。只声明已实际查看过的内容。
2. 提取商品外观、已知规格、卖点、使用场景、禁用表述，标记缺失事实。
3. 不编造认证、功效、销量、评价、优惠或参数；图片只能证明可见外观，不能证明隐藏材质和性能。不因目标国家推断清真、环保、医疗认证或消费偏好。
4. 目标市场缺失且会影响语言时，只问这一项关键问题。风格、图数等非关键项采用默认值继续。用户未指定语言时采用下表；指定语言优先。

## 2. 用自身模型策划整套内容

读取相对本文件的 [设计规范](references/design-guide.md)，自行完成策划，无须额外调用分析 API。

- 明确目标受众、已知痛点与本套图的购买理由。
- 建立共享视觉方向：商品外观锚点、配色、场景气质、字体风格、标题层级、文字位置。
- 安排首图钩子、使用场景、单个核心卖点、真实细节、购买顾虑和行动引导，按图数自然组合；不能把假评价当证据。
- 每张有独立信息任务、准确的目标语言标题和短正文，手机端一眼能读懂。
- 生成完整自然语言提示词，逐字包含要画的标题/正文，指定构图、主体、光线、文字层级、对比与安全留白。禁止把原始商品字典直接拼给生图工具。
- 生图前检查事实依据、文案拼写、每图分工和跨图一致性。输出足够具体的设计简报，不使用“爆款、好看、高转化”代替设计要求，不保证销量或流量。

## 3. 调用已有生图工具，直接生成含文字成品

识别当前会话的图像生成/编辑工具。工具如需发现，使用宿主提供的工具发现能力；只检查能力，不要求用户安装新工具。

- 例如当前宿主提供 `generate_image`，且支持 `prompt`、`reference_images`、`size`、`path`，则把完整设计简报映射到 `prompt`，商品参考图传入 `reference_images`，按说明选择支持的尺寸并保存。名称和参数以当前工具定义为准。
- 每张不同内容使用单独提示词；工具的 `n` 若只表示同一提示词的多个变体，不用它冒充整套不同内容。
- 图中文字由模型直接画入图片，不后期叠字；保留真实包装Logo，不添加虚构品牌/认证。
- 有参考图且工具支持时必须传图。若需要先上传或转换为工具能访问的资源，使用现有文件/上传工具处理，不假设本地路径对远程工具可见。
- 工具不支持参考图时，明确说明商品一致性受限；不静默丢弃参考图冒充已还原。用户允许概念图时才继续该降级路径。
- 遵守工具支持的尺寸与并发；没有明确并发支持时顺序生成。比例不支持时选择最接近的竖图并注明实际尺寸，不裁切掉图中文字。
- 返回生成任务ID时，用对应查询/等待工具继续收取结果；不要重复提交同一张。超时状态不明时先查询，避免重复计费。
- 没有可调用生图能力时，仍完成可执行策划和提示词，清楚说明未生成图片及缺少的能力；不要求填Key、不声称生成成功。

## 4. 检查、归档和交付

使用现有图像查看能力实际检查结果：商品形状/颜色/配件、文字拼写/漏字、主体与文案遮挡、跨图风格。不要只凭工具返回“成功”宣称视觉验收通过；不能检查的项目标为未核验。

- 某张失败时保留其余结果。明确失败位置与原因，先检查任务状态；针对已确定失败的单图最多自动补一次，不无限重试。
- 有明显乱码或商品变形时，只修该图；保留原版本及修订记录。无法修好则如实标注，不把问题图描述为可直接发布。
- 默认保存到当前工作区独立输出目录，例如 `tiktok-carousel/<product>-<market>-<run-id>/`，不要把结果或用户资料写进 Skill 安装目录。
- 保存实际图片及 `plan.json`、`caption.txt`。结构参照 [归档模板](templates/plan.example.json)，它是填写范例，不是可直接运行的策划。按实际图数扩展，不把占位符或示例商品事实当用户资料。
- 图片按序号和版本命名，例如 `01-v1.png`、`01-v2.png`；保持工具真实格式，不仅改扩展名伪装成另一格式。记录实际提示词、文件路径/资源ID、任务ID、版本、失败与验收状态。
- 有文件能力时使用现有工具创建ZIP，包含当前选中图片、策划及发布文案，不夹带用户参考图/密钥/历史废图。无压缩能力时交付全部文件链接，不为压缩安装依赖。
- 最后给出图片预览/链接、输出目录或ZIP、发布文案与需复核项。宿主只能返回附件或资源ID时按实际能力交付，不捏造本地路径。

## 5. 单图修改

1. 读取已有策划与该图当前版本，复用原始商品参考和整套视觉方向；只改指定页。
2. 用户只改场景/光线/构图时，保持文案逐字不变；用户明确改文字时采用其新文案。
3. 用自身模型重写完整提示词，调用现有编辑或生图工具；支持时附原图辅助定向编辑，并始终保留商品参考。
4. 写入新版本文件，更新策划的选中版本与实际提示词，保留旧文件。失败不覆盖旧的选中版本。
5. 更新当前导出包，只汇报这次改动和结果。

## 分享与使用

整个目录就是分享单位。接收方将它放入自己的 Agent 支持的 Skill 目录，或让 Agent 阅读本文件；由该 Agent 的已有模型和生图工具直接执行。宿主若在会话开始时扫描 Skill，按宿主方式刷新列表或开启新会话即可。
